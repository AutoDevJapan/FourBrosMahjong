# ADR-0002: AI(他家)方策の管理場所と現行方策

## Status

Accepted

## Date

2026-07-21

## Context

[issue #324](https://github.com/AutoDevJapan/FourBrosMahjong/issues/324) で、AI の打牌・鳴き・リーチ・カン方策を記述した文書が**どこにも存在しない**ことが指摘された(`grep -rln "AI" documents/spec/` は UI アクセシビリティポリシー1件しかヒットしない)。

方策は #98 / #169 / #294 / #295 / #303 / #304 / #322 と積み上がっているが、判断根拠はコード内 JSDoc と issue コメントに散在している。とくに #304 の「合法なら無条件にカン」→「向聴を悪化させるならカンしない」や、#323 で確定した「閾値を設けない」という決定は、コードコメントだけに埋もれてよい粒度ではない。

### 置き場所の論点

`documents/spec/` は「[`docs/四兄弟麻雀ルール.md`](../../docs/四兄弟麻雀ルール.md)(ゲームルールの SSOT)を実装可能な粒度へ分解したもの」であり、spec の各文書はルール文書の記述に対応づく。**AI の強さ・方策はゲームルールに由来しない** — ルールが許す合法手の集合の中から「どれを選ぶか」という設計判断であり、ルール文書には対応する記述が存在しない。したがって spec に置くと「spec = ルールの実装分解」という整理が崩れる。

一方 `docs/` は人間向けのゲームルール・企画ドキュメントの置き場であり、実装の設計判断は対象外。

`documents/adr/` は既に [ADR-0001](./0001-deploy-architecture-and-preview-policy.md) で運用が始まっており、「決定に至った背景・検討した選択肢・決定・結果(トレードオフ)」を残す形式は、まさに AI 方策の各判断(なぜその優先度なのか、なぜ閾値を設けないのか)に適合する。

## Decision

**AI 方策は `documents/spec/` ではなく `documents/adr/` で管理する。** 本 ADR をその集約先とする。

- ルール由来でない設計判断であるため spec の対象外とし、「spec = ルールの実装分解」という整理を維持する。
- 方策を変更する issue は、実装と同じ PR で本 ADR の該当節を更新する。
- 方策を根本から覆す決定(例: 打点期待値ベースの評価器へ置き換える)は、本 ADR を `Superseded by ADR-NNNN` にして新規 ADR を起こす。

実装は `src/domain/game/ai.ts`(純ロジック)と `src/domain/game/engine.ts`(局面との結線)に分かれる。本 ADR は**判断とその根拠**を担当し、アルゴリズムの詳細は各関数の JSDoc を参照先とする。

## 現行方策

### 前提・スコープ

- 評価は**自家の見えている情報のみ**(自分の門前牌・副露数・他家の河)。相手の手牌は覗かない。
- 受け入れはサンマの実在牌種(萬子1・9のみ / 字牌 東南西北白發中)に閉じて数える(`SANMA_TILE_KINDS`)。
- 受け入れは**標準形・七対子・国士の全てを対象に数える**。実装は計算量削減のため候補牌種を枝刈りするが、枝刈り後の結果は**全27牌種を走査した場合と厳密に同値**でなければならない(**#368**)。この同値性は不変条件であり、候補生成の条件を変える変更は必ず全牌種走査との照合テストで担保する。
- 向聴・受け入れの計算は標準麻雀の手牌効率理論に独自準拠(外部ライブラリ非依存)。40,000手のオラクル相互検証テストでアンカー済み。
- 人間(p0)には一切適用しない。AI の方策であり、UI の選択肢を狭めてはならない。

### 打牌(`chooseDiscard`)

優先度順に比較する(上位が同点のときのみ下位を見る):

1. **打牌後の向聴数**(小さいほど良い)
2. **受け入れ延べ枚数**(大きいほど良い) — ただし**向聴最小の候補が複数あり、かつ `UKEIRE_SHANTEN_GATE = 1`(1向聴以下)のとき**にのみ算出する。2向聴以遠は受け入れがほぼ横並びで打牌選択にほぼ影響しない一方、計算量が跳ね上がるため(#98)
3. **打点温存価値**(赤5=2・ドラ=1・素牌=0。小さいほど切ってよい) — オール赤5・サイコロドラという本作固有のルールを打牌の価値付けへ反映する
4. **危険牌回避**(現物にしている他家の数。多いほど切ってよい) — 現物の判定は他家の**打牌履歴**を入力にする。鳴かれて河から消えた牌もその家に対する現物であり続ける(**#395**)
5. **外側度**(字牌 > 老頭 > 端寄り) — 同点時の決定的タイブレーク

副露手の向聴は `meldCount` で補正する(**#294**)。未補正だと副露手で向聴値が飽和し、テンパイ維持打牌と崩し打牌が同点になってタイブレークがテンパイを壊していた。

優先度2の受け入れは**七対子・国士の有効牌も数える**(**#368**)。従来の候補枝刈りは「向聴を進める牌は既存牌と面子/塔子/対子を作れるもの(同種または同スート±2)に限る」という標準形の性質だけに依拠しており、七対子の7種類目になる未所持牌と、国士の未所持么九牌を候補から落としていた。その結果、門前の七対子・国士手で受け入れが過少に出て、タイブレークが本来より狭い待ちの打牌を選び得た(例: 国士テンパイ `11m 9m 19p 19s 123456z` の受け入れが 0 種 0 枚)。枝刈り自体は残し、**七対子/国士の向聴が現在の全体最小と一致するときだけ**その役種固有の候補を和集合することで、標準形の探索母数を維持したまま全牌種走査と同値にしている。

喰い替え禁止牌(**#105**)は**手牌から削らず**、打牌候補としてのみ除外する(**#303**)。手牌から削ると評価対象が `14 − 3×副露数` 枚を下回り、向聴が実際より悪く出て `UKEIRE_SHANTEN_GATE` の発火条件までずれる。

> **フィクスチャ注意**: 手牌枚数が `14 − 3×副露数` を破ると向聴評価が静かに壊れる。この取り違えは #303 / #320 で2度事故になっている。テストフィクスチャには必ず枚数ガードを入れること。

### 鳴き(`shouldCallMeld`)

ナシナシ規則下で役無しを確定させないための最小限の判断。**今回の鳴きで役牌(三元牌・場風・自風)を確定するか、既に役牌の副露があって役が確定済みの場合だけ鳴く。** ドラは役ではなく、鳴いた後は門前へ戻れないため判断材料にしない。

> **重要**: 役牌限定なのは**最初の1副露だけ**である。役牌の副露が1つでもあれば、以後は**任意の牌**を鳴く。「AI は役牌しか鳴かない」という要約は誤りで、この誤解が #322 の原因になった(下記)。

### リーチ

門前テンパイなら宣言する。供託・合法牌の判定は人間と同じ述語を使う。

**フリテンになる宣言牌ではリーチせずダマに留める**(**#295**)。フリテンのままリーチすると自分のロン和了が封じられたまま手が固定される。

この判定も自分の**打牌履歴**を入力にする(**#395**)。表示用の河は鳴かれた牌が取り除かれるため、河を入力にすると鳴かれた分だけフリテン判定が緩み、AI がフリテンのままリーチし得た(#295 の退行経路)。

**定量**: 現物集合・自河集合はいずれも河から履歴へ切り替えると**単調に広がる**(履歴 ⊇ 河)ため、方策の変化は「鳴かれた牌ぶんだけ安全側に寄る」一方向に限られる。#295 の回帰スイート(seed 1/9/18/25/27 の半荘完走)ではフリテンリーチ 0 件・リーチ発生件数ともに変化なし。**既存の seed 固定テストで期待値の更新を要したものは 0 件**(`ai.test.ts` / `ai.call.test.ts` / engine の AI 系テストすべて)。したがって現行の AI 方策に観測可能な軌跡変化は無く、変わるのは**鳴きが絡む局面での判定の正しさのみ**である。

リーチ後は自動ツモ切りが基本(ツモ和了のみ選択の余地)。ただし**送り槓にならない暗槓は許可**する(標準慣行 / Q18・#116)。`canAnkanAfterRiichi` が待ち牌集合の不変を要求する。

### カン

自ツモ番では**加槓 → 暗槓**の順に合法なカンを探す。海底では宣言しない。

**向聴を悪化させるカンは宣言しない**(**#304**)。順子・塔子に使っている牌を槓に回すとその牌が面子として固定されて待ちが崩れる(例: `456s` を持った状態で4枚目の `5s` を暗槓すると `4s` `6s` が孤立する)。従来は合法なら無条件に宣言しており、AI が自らテンパイを落としていた。

判定(`kanKeepsShanten`)は**打牌後13枚相当**の向聴に揃えて比較する(嶺上牌はこの時点で未知のため評価に含めない):

| 種別 | 基準値(カンしない場合) | カン後 |
|---|---|---|
| 暗槓 | `min over 打牌 d of shanten(pool − d, 副露数)` | `shanten(pool − 4枚, 副露数 + 1)` |
| 加槓 | 同上 | `shanten(pool − 1枚, 副露数)`(ポン→カンで面子数は不変) |
| 大明槓 | `min over 打牌 d of shanten(pool − 3枚 − d, 副露数 + 1)`(= ポン後の最良形) | `shanten(pool − 4枚, 副露数 + 1)` |

`カン後 <= 基準値` のときだけ宣言する。

**ドラ増加による打点上昇とのトレードオフは、向聴維持を優先する**。この判断は #323 で 4,000半荘の A/B により検証済み(下記「定量結果」)。

#### 大明槓(#322)

大明槓では「カンしない」の対案が**打牌しないこと**ではなく**同じ牌をポンすること**である(`shouldCallMeld` が真の局面でのみ判定するため、鳴くこと自体は既に決まっている)。したがって基準値をポン後の最良形に取り、**悪化する場合は見送るのではなくポンへ落とす**。役牌の役を確定させる目的は達成しつつ、4枚目を手牌に残して面子・塔子として使える。

この適用は当初「`shouldCallMeld` が役牌にしか鳴きを許さないので大明槓は原理的に安全」という理由で見送られていたが、**その前提が誤り**であることが判明した(上記のとおり役牌限定は最初の1副露だけ)。#320 時点の「実測0件」は seed 1〜400 かつ自家がツモ切り方策での観測であり、自家に `chooseDiscard` を与えて 4,000半荘へ広げると**88件の向聴悪化する大明槓**が観測された。

#### 閾値を設けない理由(#323)

向聴悪化の抑制は**閾値を設けず全向聴域で一律に適用**する。抑制の 77% は1向聴以遠(深い向聴では新ドラ+嶺上ツモ+赤の期待打点が向聴1手ぶんの損を上回る可能性があった)だが、4,000半荘の A/B で打点・和了率の犠牲は観測されず、閾値2との差は 0.01σ で調整点を増やす利得がないと実証された。

## 定量結果

方策変更の検証は「半荘シミュレーションの before/after」で行う。**エンドオブ半荘のソシー収支では効果量が小さすぎて解像できない**(#320 の A/B で ≤0.21σ)ため、**カン宣言数・向聴悪化件数といった直接指標を必ず併記する**。

| issue | 手法 | 主要な結果 |
|---|---|---|
| #304 / [PR #320](https://github.com/AutoDevJapan/FourBrosMahjong/pull/320) | seed 1〜800、2種の自家方策 | カン直後の打牌でテンパイ→ノーテン転落が **42→0 / 34→0**。カン宣言数 820→692 |
| #323 | 4,000半荘 A/B | 閾値なし vs 閾値2 の差は **0.01σ**。打点・和了率の犠牲なし → 閾値を設けない決定 |
| #322 | 4,000半荘 A/B(自家も `chooseDiscard`) | 大明槓 1,944件中 **88件 (4.5%) が向聴悪化**、うち **66件はポンならテンパイを保てた**。適用後、大明槓 1,944→1,858(概ね悪化件数ぶん減。before/after で seed 対応は取れないため厳密一致しない)・ポン 26,607→26,711。平均ソシー差 **−0.0002σ**(有意差なし)・平均順位差 −0.00125・和了率 18.46%→18.46%・平均打点 9,744→9,733・放銃率 17.83%→17.82% |
| #322 | seed 1〜800 | 大明槓 377件中 **14件が向聴悪化**(うち6件はテンパイ破壊)。適用後 377→363 と悪化件数ぶんだけ正確に減少 |

計測ハーネスは**コミットしない**(一時スクリプトはリポジトリ外へ置く)。再現に必要な条件(seed 範囲・自家方策・計測指標の定義)を PR 本文と本表に残すことで代替する。

> **注意**: 自家(p0)の打牌方策が変わると局の進行が丸ごと変わるため、**方策の異なる計測どうしで seed の対応は取れない**。before/after は必ず同一ハーネス内で比較すること(#320 で issue 本文の数値が再現できなかった原因)。

## Consequences

### 良い点

- AI 方策の判断と根拠が1か所に集約され、「なぜこの優先度か」「なぜ閾値がないか」がコードを読まずに追える。
- `documents/spec/` の「ルールの実装分解」という位置づけを維持できる。
- 方策変更時の検証手法(直接指標を併記する)が明文化され、#320 で判明した「ソシー収支だけでは解像できない」という教訓が失われない。

### 悪い点・受け入れるトレードオフ

- 実装と ADR の二重管理になる。方策を変える PR で ADR 更新を怠ると陳腐化する — レビュー時のチェック項目として運用でカバーする。
- 本 ADR は方策の**判断**を記述し、アルゴリズムの詳細は JSDoc に委ねている。両者の粒度の境界は厳密ではない。

### 既知の未解決事項

- **打点を含む評価器は存在しない**。現行の指標は向聴・受け入れ・温存価値のヒューリスティックであり、期待打点の最大化ではない。
- 鳴き判断は役牌の有無のみで、**手牌の価値(向聴・打点)を見ていない**。`shouldCallMeld` を広げる際は、大明槓と同様に向聴悪化ガードの適用範囲を再検討すること。
- 危険牌回避は「現物」のみで、筋・壁・リーチ者の河読みは行わない。
