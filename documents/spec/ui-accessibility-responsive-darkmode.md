# スペック5: アクセシビリティ・レスポンシブ・ダークモード横断方針

対象: 個別UIコンポーネントではなく、以降のUI実装(#8 ゲーム画面設計、#9 トップページ置き換え等)全体が従うべき横断方針。
本スペックは **方針の確立のみ** を範囲とし、個別コンポーネントの実装は含まない([Issue #13](https://github.com/AutoDevJapan/FourBrosMahjong/issues/13))。

## 5.1 背景

麻雀卓UIは次の理由で情報密度が高く、色依存になりやすい。

- 牌の判別(萬子/筒子/索子、赤ドラ)、点数の増減、手番表示など、色だけに頼った表現になりがちな要素が多い
- 4人分の卓レイアウトを持つため、狭幅画面での成立方法を早期に決めないと後戻りコストが大きい
- `globals.css` は現在 `@media (prefers-color-scheme: dark)` によるデフォルト追従のみで、手動トグルは未対応

以降の各方針は、実装issue(#8, #9 等)がこの文書を参照して従うことを前提とする。

## 5.2 アクセシビリティ方針

### 5.2.1 色のみに依存しない情報伝達

| 対象 | 色以外の伝達手段 |
|---|---|
| 牌の種類(萬子/筒子/索子/字牌) | 牌面の印字(漢数字・記号)自体が識別情報を持つため、色は補助情報に留める。実装上も `aria-label` にスート名+数字を含める(例: `aria-label="五筒"`) |
| 赤ドラ(オール赤5) | 色(赤)だけでなく、牌面に赤枠/バッジ等の形状差を付与し、`aria-label` に `(赤ドラ)` を付記する(例: `aria-label="五筒(赤ドラ)"`) |
| 点数の増減 | `+`/`-` の符号とテキスト表示を色(緑/赤)と併用する。色のみでの増減表現は禁止 |
| 手番・現在ターン表示 | ハイライト色に加え、アイコン(▶等)またはテキストラベルを併記する |
| 場況(リーチ・鳴き・北抜き等の状態) | アイコン/テキストラベルを併記し、色のみのバッジにしない |

### 5.2.2 キーボード操作・フォーカス可視化

- 打牌・鳴き(ポン/カン)・リーチ宣言・北抜き確認など、すべての操作はマウス/タップ操作と同等にキーボードのみで完結できること(`Tab` で到達、`Enter`/`Space` で決定)
- 手牌のようなタイル一覧は [WAI-ARIA APG の Listbox/Toolbar パターン](https://www.w3.org/WAI/ARIA/apg/patterns/) に準拠したロービングタブインデックスで矢印キー移動を提供する
- フォーカスリングは `outline: none` 等で除去しない。除去する場合は同等以上の視認性を持つ代替(独自 `:focus-visible` スタイル)を必ず用意し、隣接背景とのコントラスト比 3:1 以上を確保する
- モーダル/ダイアログ表示中はフォーカストラップを行い、`Escape` で閉じられること
- モーダル/ダイアログ表示中は**背後のコンテンツをアクセシビリティツリー・フォーカス順から除外**する(`inert` 等)。特に「全体盤面」モーダルは 5.3.2 段階②の盤面をダイアログ内へ再掲するため、背後の盤面本体を除外しないと自家 region・手牌 listbox 等のアクセシブル名がスクリーンリーダへ二重提示される。閉じたら**トリガー(「全体盤面」ボタン)へフォーカスを復帰**する(`inert` はトリガーからフォーカスを奪うため、閉時に明示復帰する)

### 5.2.3 スクリーンリーダ向けライブリージョン

| イベント | `aria-live` | 用途 |
|---|---|---|
| 手番交代・ドラめくり・リーチ宣言等の局進行 | `polite` | 進行を妨げずに通知 |
| 和了(ツモ/ロン)・流局・半荘終了などの結果確定 | `assertive`(または `role="alert"`) | 即時に注意を引く必要がある確定イベント |

- 通知文言は簡潔にし、連続更新によるスクリーンリーダの読み上げ渋滞を避ける(同一フレーム内の複数更新はまとめて1回で通知する)

### 5.2.4 コントラスト比の目標

- **WCAG 2.1 AA** を最低ラインとする
  - 通常テキスト: 4.5:1 以上
  - 大きいテキスト(24px以上、または太字18px以上)・アイコン等の非テキストコントラスト: 3:1 以上
- ライト/ダーク両テーマで上記を満たすことを配色トークン設計時に確認する(5.4節)

### 5.2.5 名前付きリストの `role="list"` 明示

Tailwind v4 preflight は `ul { list-style: none }` を全リストへ適用する。Safari は装飾(リストマーカー)を外した `<ul>`/`<ol>` から list セマンティクスを除去する既知のヒューリスティクスを持ち、VoiceOver がリスト構造を(場合により `aria-label` による名前ごと)読まなくなる。axe や Testing Library / Playwright の role クエリは Chromium 系のアクセシビリティツリーを見るため、この WebKit 実挙動は自動テストでは検出できない。

- **規約**: アクセシブル名(`aria-label` / `aria-labelledby`)を持つ `<ul>`/`<ol>` には `role="list"` を明示する。HTML 仕様上は冗長(redundant role)だが標準的な既知の対処であり、意図をコメントで明記する
- `role="listbox"` 等、別のロールを明示しているリストは対象外(そのロールが優先される)
- アクセシブル名を持たないレイアウト用リストへの明示は必須としない(名前付きグループとして伝える意図がないため)
- コンポーネントテストでは `toHaveAttribute("role", "list")` で明示を回帰検証する。role クエリ(`getByRole("list")`)は暗黙ロールでも通るため、明示の欠落を検出できない

適用済み: `DoraIndicator`(#261 / #269)、`Melds`・`Discards`・`Hand`(閲覧専用リスト)・`WinDetails`(和了形/成立役/支払い内訳)(#270)。

## 5.3 レスポンシブ方針

### 5.3.1 対象ブレークポイント

Tailwind v4 のデフォルトブレークポイントをそのまま採用し、独自のブレークポイント追加は行わない(`tailwind.config.*` を持たない本プロジェクトの方針と整合)。

| 呼称 | Tailwind v4 デフォルト | 想定デバイス |
|---|---|---|
| ベース(既定) | `< 640px` | スマートフォン縦持ち |
| `sm` | `>= 640px` | スマートフォン横持ち・小型タブレット |
| `md` | `>= 768px` | タブレット縦持ち |
| `lg` | `>= 1024px` | タブレット横持ち・小型デスクトップ |
| `xl` | `>= 1280px` | デスクトップ |

- 主要な設計対象は **スマホ縦(ベース) / タブレット(`md`) / デスクトップ(`lg`以上)** の3段階とする。`sm`/`xl` は補助的な微調整用に留める。
- 新しいカスタムブレークポイントが必要になった場合は、Tailwind v4 の `@theme` の `--breakpoint-*` トークンとして `globals.css` に追加し、CSS外(JS設定ファイル)を増やさない。

### 5.3.2 狭幅時の四人卓レイアウト方針

- 基準レイアウト(`md`以上): 卓を中心に4人分の手牌/捨て牌/得点表示を上下左右(または自分下・対面上・左右)に配置するクロス/ロータリー型レイアウトとする
- 狭幅(ベース、`< 640px` 目安)では次の2段階で成立させる:
  1. **スケーリング優先**: `clamp()` とコンテナクエリ相当(Tailwind v4 の `@container` 対応)で卓全体を縮小し、横スクロールを発生させない
  2. **縮小が視認性を損なう幅(目安: 卓の描画幅が360px未満)を下回ったら「自分手番フォーカス表示」に切替**: 自分の手牌・操作パネルをフルサイズで表示し、他家3人分は捨て牌の直近数枚+得点+状態アイコンのみのコンパクト帯として表示する。全体盤面は折りたたみ/モーダルでいつでも確認できるようにする
- いずれの段階でも横スクロールでのレイアウト成立(はみ出しを横スクロールで解決する手法)は採用しない

## 5.4 ダークモード方針

### 5.4.1 結論: 自動追従 + 手動トグルの併用

- `prefers-color-scheme` によるOS設定追従を**既定値**として維持する(現状の `globals.css` の挙動を踏襲)
- そのうえで、**手動トグルを追加する**(自動追従のみで終わらせない)。理由:
  - 対局は1半荘が長時間に及び、環境光の変化やOS設定と無関係にユーザーが好みを固定したい場面がある
  - 牌の視認性(色の正確な判別)はゲーム性に直結するため、ユーザーが意図的にテーマを固定できる必要がある
- 実装方式(次回以降の実装issueに引き継ぐ指針):
  - `data-theme="light"|"dark"` を `<html>` に付与し、Tailwind v4 は `@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));` 相当のカスタムバリアントで `dark:` を有効化する
  - ユーザーが未選択の場合は `data-theme` を付与せず `prefers-color-scheme` に委譲し、明示選択時は `localStorage` に保存してOS設定より優先する
  - トグルUI自体の実装は本issueのスコープ外(#8 等のUI実装issueで行う)

### 5.4.2 配色トークン設計方針

- `globals.css` の `:root` にセマンティックなCSSカスタムプロパティとして定義し、コンポーネント側は生の色値を直接使わずトークン経由で参照する
- 最低限、以下のトークン群をライト/ダークそれぞれで定義し、5.2.4 のコントラスト目標を満たす値を設定する

| トークン(例) | 用途 |
|---|---|
| `--background` / `--foreground` | 既存踏襲。ページ全体の基調色 |
| `--color-table-felt` | 卓の背景(緑系felt色) |
| `--color-tile-face` / `--color-tile-border` | 牌面・牌の縁取り(非テキスト境界)。白地に直接載る手牌の枠はページ背景 `--background` に対しライト/ダーク双方で 3:1 以上(1.4.11 / 5.2.4)。フラット1色では白地と緑フェルトを同時に満たせないため白地側を基準にし、フェルト上の輪郭は牌面 `--color-tile-face` の高コントラストが担う(#148)。`--color-tile-face` は felt 上の状態バッジ(`StatusBadge` 全バリアント)の地色も兼ね、felt に対し非テキスト 3:1 以上でバッジを図地分離する(#154 / #157) |
| `--color-tile-ink` | 牌面の印字色(テーマ非依存の濃色)。felt 上の状態バッジ `default`(◆親)の文字色を兼ね、明色地 `--color-tile-face` に対しライト/ダーク双方で 4.5:1 以上(1.4.3)。felt 直載せの半透明前景色ではライトで 2.35:1 と不足するため、明色地+濃色印字へ是正した(#157) |
| `--color-tile-accent-red` | 赤ドラの強調色=牌枠(非テキスト)。隣接色に対し 3:1 以上(5.2.4) |
| `--color-tile-badge-red` | 赤ドラ「赤」バッジの地色(テキスト背景)。文字 `--color-tile-face` に対しライト/ダーク双方で 4.5:1 以上(1.4.3)。ダークで枠を鮮やかな赤へ上げると文字比が割れるため枠とは別トークンに分離し、テーマ非依存の深い赤で固定する(#147) |
| `--color-turn-highlight` | 現在手番のハイライト(枠・リング・セクション地の淡色重畳)。文字色には使わない(→ 明色地上のバッジ文字は `--color-turn-highlight-ink`、淡色地上のボタン文字は `--color-turn-highlight-strong`)。非テキスト用途では隣接色に対し 3:1 以上(5.2.4) |
| `--color-turn-highlight-ink` | 状態バッジ「手番」の文字色。felt 上のバッジは明色地 `--color-tile-face` を敷きその上に描くため、地に対しライト/ダーク双方で 4.5:1 以上(1.4.3)。`--color-turn-highlight` はダークで明色 #f59e0b へ振れ明色地上では文字比が割れるため、テキスト用に別トークンへ分離しテーマ非依存の濃い琥珀で固定する(#154) |
| `--color-turn-highlight-strong` | 操作パネル(`ActionPanel`)主要ボタンの文字色。ボタン地は `--color-turn-highlight` を 10% 敷いたテーマ連動の淡地(ライト)/濃地(ダーク)のため、地の上でライト/ダーク双方 4.5:1 以上(1.4.3)。地がテーマ連動で反転する点が明色地固定の `--color-turn-highlight-ink` と異なり流用できないため、ライト=濃い琥珀・ダーク=明るい琥珀と地に応じて反転する専用トークンへ分離する(#159。以前は `--color-turn-highlight` を文字に流用しライトで 4.39:1 と不足していた) |
| `--color-danger` / `--color-positive` | 点数減少/増加、トビ警告等 |
| `--color-focus-ring` | フォーカスリング(隣接背景に対し3:1以上) |

- 新規トークン追加時は、ライト/ダーク双方でコントラスト計算(5.5節のツール)を通してからマージする

## 5.5 アクセシビリティ検証手段

| 手段 | 種別 | 適用タイミング |
|---|---|---|
| `eslint-config-next`(`core-web-vitals`)同梱の `jsx-a11y` ルール | 静的解析 | 既存の `pnpm lint` に含まれる(追加設定不要、既に有効) |
| `@axe-core/playwright` | 自動E2E監査 | Playwright E2E基盤整備(#11)のタイミングで導入し、主要画面のアクセシビリティ違反を自動検知するシナリオを追加する。初期局面だけでは走査外となる局面依存の動的描画(狭幅コンパクト帯/全体盤面モーダル #148、リーチ宣言バッジ・鳴き副露・和了/流局の `role="alert"` 通知・`--danger`/`--positive` 点差 #159)は、実対局を進めて DOM に出現させた状態で監査する「状態駆動シナリオ」で補完する。到達が非決定的な局面は、`GameProvider` の決定的再現フック(`/game?seed=<整数>`、本番導線=クエリ無しでは不発)で固定し安定再現する |
| Lighthouse(Accessibility カテゴリ) | 手動/CI監査 | プレビュー環境整備(#3)後、主要画面で定期実行しスコアを記録する |
| Playwright ダークモードシナリオ | 手動/自動E2E | `prefers-color-scheme: dark` エミュレーションおよび手動トグル操作の双方で主要画面のスクリーンショット/コントラストを確認するシナリオを #11 で追加する |
| キーボードのみ操作・スクリーンリーダ(NVDA/VoiceOver等)による手動確認 | 手動 | 主要フロー(打牌・鳴き・リーチ・和了通知)実装時にリリース前チェックとして実施する |
