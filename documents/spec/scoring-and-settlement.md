### 後付け(ナシナシ=完全先付け寄り)の厳密定義 【判断ポイント / #83-2】

「後付けなし」を**完全先付け寄り**として次のとおり確定する:

- **唯一の役が「和了牌で完成した役牌(三元牌・場風・自風の暗刻)」だけの手は和了不可**とする。
  - 具体的には「役牌刻子が暗刻(`concealed`)で、かつ和了牌がその刻子を完成させた」ケースを後付けとみなす。既に確定していた役牌(副露のポン・和了前から成立していた暗刻)や、和了牌が別グループ(雀頭・順子・他刻子)を完成させた場合は後付けに当たらない。
- **門前・副露の双方**に適用する(門前ダマで役牌が和了牌完成のみ、も不可)。
- 役牌以外の役(門前ツモ・平和・対々和・断么九 等)が1つでもあれば和了可。**役満は本制約の対象外**(常に和了可)。

> **確定の位置づけ**: 関西サンマは完全先付けが自然(店ルールとしても一般的)なため本案を採用。**番組の一次情報が無い判断点であり、実装(#65)とともに見直し得る。**

### 北(ガリ)を手牌に残した刻子・雀頭の役牌扱い 【判断ポイント / #83-3】

- 北は**抜きドラ(ガリ)**であり、抜かずに手牌で刻子にしても**役牌1翻としない**。
- 手牌に残した北刻子は「役の無い字牌刻子」として扱う。対々和・混一色・字一色 等の**構成要素**にはなり得るが、それ自体で**役牌翻は発生しない**(抜いた北のドラ1翻=3.2 とは別枠で、二重取りしない)。
- 同じ理由で、**北は雀頭でも役牌として扱わない**。平和の否定条件「役牌(三元牌・場風・自風)雀頭」に北は該当せず、**北雀頭は平和を否定しない**(#400)。なお現行ルールでは北が風に割り当たること自体が無い(**自風**: 四人回しで北家=抜け番 → スペック2 2.5 席・親・抜け番の回転 / **場風**: 東南戦のため場風は東・南のみ → 同 2.6)が、この契約は風の割り当てに依存せず成り立つ。
- 刻子側と同じく、**役牌でないこと**と**風牌であること**は別である。北雀頭は小四喜の「風牌雀頭」(上表)・字一色・混老頭 等の**構成要素にはなり得る**。
- 本節の「北を抜かずに手牌へ残す」前提は、現行実装では到達不能である(北は全経路で自動的に抜かれる)。→ **質問リスト Q32**(北抜きは強制か任意か)の裁定待ち。

> **確定の位置づけ**: 抜きドラ運用との二重取りを避ける自然な解釈。**番組の一次情報が無い判断点であり見直し得る。**

|---|---|---|---|
| 1〜4 | 通常 | → 下記「4翻以下の標準点」 | 同左 |
| 5 | 満貫 | 8,000 | 12,000 |

### 4翻以下の標準点(符計算なし・一律30符相当)【判断ポイント / #89-1】

spec は「符計算を行わない」とだけ定めるが、翻のみでは点数が一意に定まらない(符が未定義)。実装 `src/domain/scoring/points.ts`(#66 / PR #88)は **1〜4翻を一律30符相当**とみなし、基本点 `a` を次式で決める:

```
a = min(30 × 2^(2+han), 2000)
```

- 30符固定・満貫上限(`a ≤ 2000`)で頭打ちする(4翻でも `a=1920 < 2000` のため通常点のまま。切り上げ満貫は採らない)。
- ロン総額 = `ceil100(a × 4)`(子)/ `ceil100(a × 6)`(親)。端数は**100点単位で切り上げ**。
- ツモ配分は 3.1 の北家折半(ツモ損なし)ロジックを下位翻にも同一適用:子ツモ 親払い=`ceil100(a×2.5)`・子払い=`ceil100(a×1.5)`、親ツモ 子各払い=`ceil100(a×3)`。

**確定テーブル(実装 `points.ts` と一致・単位: 点):**

| 翻 | 基本点 `a` | 子ロン | 親ロン | 子ツモ(親払い / 子払い) | 親ツモ(子各払い) |
|---|---|---|---|---|---|
| 1 | 240 | 1,000 | 1,500 | 600 / 400 | 800 |
| 2 | 480 | 2,000 | 2,900 | 1,200 / 800 | 1,500 |
| 3 | 960 | 3,900 | 5,800 | 2,400 / 1,500 | 2,900 |
| 4 | 1,920 | 7,700 | 11,600 | 4,800 / 2,900 | 5,800 |

> **端数の注記**: 各支払額を独立に切り上げるため、**低翻の親ツモは総額がロンをわずかに上回る**(1翻: 子各800×2=1,600 > 親ロン1,500 / 2翻: 1,500×2=3,000 > 親ロン2,900、いずれも+100)。「ツモ損なし(ツモ総額=ロン)」の厳密一致は満貫以上でのみ成立する。実装の切り上げ順序に忠実な確定挙動として扱う。

> **確定の位置づけ**: 一律30符は関西サンマの符省略運用として自然な近似であり、**実装(#66)のデフォルトをそのまま確定仕様とする**(#79/#83 と同方針)。番組の一次情報に符・下位翻の点数表は無く、**切り上げ満貫化や別の固定テーブルへの差し替え余地を残す**。ガリ・オール赤5・複数ドラで満貫以上が頻発する想定のため、4翻以下の点数差の実運用インパクトは限定的。

### ツモ和了時の支払い配分(ツモ損なし・北家折半方式)(Q12)

サンマは**北家(4人目)が不在**のため、不在の北家が負担するはずの分を**親と子で折半**して負担する。これにより**ツモ和了者はロンと同額を受け取る**(いわゆる「ツモ損なし」・西日本サンマ主流)。親被りは通常どおり親が子の2倍を負担する。

**標準区分の支払い対応表(単位: 点):**

| 区分 | 子ツモ(親払い / 子払い) | 親ツモ(子各払い) |
|---|---|---|
| 満貫 | 5,000 / 3,000 | 6,000 |
| 跳満 | 7,500 / 4,500 | 9,000 |
| 倍満 | 10,000 / 6,000 | 12,000 |
| 三倍満 | 15,000 / 9,000 | 18,000 |
| 役満 | 20,000 / 12,000 | 24,000 |

**受取合計(いずれもロンと同額になる = ツモ損なし):**

- **子ツモ**: 支払者は**親1人+子1人**(サンマの着席は東/南/西で、子和了時の払い手は親と残り1子)。受取合計 = 親払い + 子払い(例: 満貫 5,000 + 3,000 = **8,000** = 子ロンと同額)。
- **親ツモ**: 支払者は**子2人**(南・西)。受取合計 = 子各払い × 2(例: 満貫 6,000×2 = **12,000** = 親ロンと同額)。
- **4翻以下も同アルゴリズム**で算出する(親被り=親が子の2倍)。

**擬似アルゴリズム(北家折半・ツモ損なし)**

`u` を標準の基本支払単位(4人打ち相当の1子分。満貫 `u=2000`、親満貫 `u=4000` … 標準テーブル準拠)とする。**不在の北家席が本来払う `1u` を、実在の払い手へ均等に上乗せ**する。

```
tsumoSplit(u_child, u_dealer, winnerIsDealer):
  # u_child = 子和了時の1子分, u_dealer = 親和了時の1子分(=標準4人打ちの1子払い)
  if winnerIsDealer:
    # 親ツモ: 4人打ちなら子3人が各 u_dealer。不在北家の u_dealer を
    # 実在の子2人へ均等分配(+u_dealer/2 ずつ) → 子各 1.5*u_dealer
    return { eachChild: 1.5 * u_dealer }        # 満貫 u_dealer=4000 → 6000
  else:
    # 子ツモ: 4人打ちなら 親 2u_child + 子2人 各 u_child。
    # 不在北家(子)の u_child を 実在の払い手(親+子)へ均等分配(+u_child/2 ずつ)
    fromDealer = 2 * u_child + u_child / 2       # 満貫 u_child=2000 → 5000
    fromChild  = 1 * u_child + u_child / 2       #                  → 3000
    return { fromDealer, fromChild }
```

> 上表を SSOT とし、下位翻(4翻以下)も同じ北家折半ロジックを適用する。ロン時は北家折半を行わず標準テーブル(3.1 冒頭表)どおり(子8,000 / 親12,000 等)。端数は百点単位で切り上げる慣行に従う。

### 本場・パオ・供託の点数移動と加算順序(端数の扱い)【判断ポイント / #89-2】

3.1 の点数を実際の持ち点増減へ落とす際、**本場加算・パオ(点数の責任払い)・供託回収**の合成順序を確定する。実装 `src/domain/scoring/win-payment.ts`(#66 / PR #88)を SSOT とする。ここでのパオは**点数の責任払い**であり、祝儀のパオ(3.3③)とは別枠(祝儀の支払者はパオでも「全員から1,000」を維持)。

**本場加算(標準の1本300点/100点)**

| 和了種別 | 本場負担 |
|---|---|
| ロン | 放銃者が `300 × 本場` を追加負担(パオ有無を問わず放銃者持ち) |
| ツモ | **各支払者**が `100 × 本場` を追加負担(支払人数分だけ場に乗る) |

**パオ(役満の責任払い)と本場の複合**

| ケース | 素点の負担 | 本場の負担 |
|---|---|---|
| パオ・ロン(責任者 ≠ 放銃者) | 点数を折半: 責任者 `ceil100(total/2)`、放銃者 `total − ceil100(total/2)` | 放銃者が `300 × 本場`(折半しない) |
| パオ・ロン(責任者 = 放銃者) | その1人が全額 `total` | 同上(放銃者=責任者が `300 × 本場`) |
| パオ・ツモ | **責任者が全額** `tsumo.total` を負担(他家は0) | 責任者が `300 × 本場`(**簡略**) |

- **加算順序**: ①素点(パオ折半を含む点数移動)→ ②本場加算、の順で `deltas`(総和ゼロ)に積む。供託(リーチ棒)は `deltas` に含めず `stickPayout = 本数 × 1,000` として和了者へ別枠加算する。
- **端数**: パオ・ロンの折半のみ `ceil100(total/2)` で100点単位に切り上げ、放銃者側が残差を負担する(役満32,000等では厳密に16,000/16,000)。パオ対象は構成役満のみで、その総額は基本点 `8,000 × 役満倍数` の4倍(子)/6倍(親) = **必ず200の倍数**(32,000 / 48,000 / 64,000 / 96,000 …)になるため、**この端数処理は現状到達しない**。点数体系やパオ対象を変えたときに切り上げ側が静かに入れ替わらないよう、確定挙動として規定し回帰テストで固定している(`src/domain/scoring/win-payment.test.ts` / #389)。到達不能な分岐を「削除する / 注記して残す」の一般方針は `質問リスト.md` の Q26・Q29 と同型の論点であり、本項はそれらの裁定が出るまで「注記して残す」側に立つ。

> **簡略の明記**: **パオ・ツモ×本場の複合**では、本来ツモの本場は各支払者が `100×本場` を分担するが、責任者が全額を負担する構図に合わせ、**本場も責任者が `300×本場`(ロン相当の一括)で負担**する簡略実装とする。パオ・ツモ・本場が同時に立つ極端ケースは実運用でほぼ発生しないため、この簡略を確定挙動とし、必要時に見直す(#79/#83 と同方針)。

| 裏ドラ | リーチ和了時のみ、表と同枚数分 |
| 赤5(オール赤5) | 手牌中の赤5筒・赤5索 1枚1翻 |
| ガリ(北抜き) | 抜いた北 1枚1翻 |

表ドラ枚数(サイコロ出目→1〜3枚)と、王牌内の表示牌の選定位置・裏ドラの開示条件は→ スペック2 2.2(重複記載しない)。

### 抜いた北 × 実ドラ北の二重取り(Q16)【確定・ユーザー承認 2026-07-17】

**確定: 二重取りする(天鳳サンマ流)。** 風牌の次牌巡回(下表)より、**ドラ表示牌が「西」のとき実ドラは「北」**になる。このとき、既に抜いて場に晒した北(ガリ)を**表/裏ドラの照合対象にも含めて**重ねて数える。すなわち抜いた北 n 枚は、

- **ガリ n翻**(上表「ガリ(北抜き)」枠)に加えて、
- ドラ表示牌が西(実ドラ=北)なら **表ドラ n翻**、リーチ和了なら裏表示牌が西のときさらに **裏ドラ n翻** を加算する。

赤5(オール赤5)とは独立に加算する(北は赤5になり得ないため相互に影響しない)。手牌に残した(抜かない)北も従来どおり実ドラ北として別途数える(抜き北とは各々1枚1翻)。ドラ表示牌が西以外(実ドラ≠北)なら抜き北は二重取りされず、ガリ翻のみとなる。

> **確定の位置づけ**: 一般的な三人麻雀(天鳳サンマ等)で広く採られる運用であり、打点インフレを是とする本変種(3.1・4)の趣旨とも整合する。番組の一次情報に明記はないが、ユーザー承認により本案を確定仕様とする(Q16 / issue #112)。実装は `src/domain/dora/han.ts`(`countDoraHan` が `kitaCount` 分の北を表/裏ドラ照合に含める)。

### 次牌写像(ドラ表示牌 → 実ドラ)

表ドラ・裏ドラは、**表示牌の「次の牌」**が実ドラになる(標準の次牌ルール)。翻集計は実ドラの**牌種(種別・数)で照合**する。写像は以下:

| 表示牌の種別 | 次牌(実ドラ)の巡回 |
|---|---|
| 筒子 | 1→2→…→9→1(9 の次は 1) |
| 索子 | 1→2→…→9→1(9 の次は 1) |
| 萬子 | **一萬↔九萬**(一萬→九萬、九萬→一萬)※本変種固有(下記) |
| 風牌 | 東→南→西→北→東 |
| 三元牌 | 白→發→中→白 |

**本変種固有ルール(萬子 一萬↔九萬)**

- 本変種の萬子は **一萬・九萬のみ**で、2〜8萬が存在しない(1.2)。そのため通常の「次の数牌」(例: 一萬→二萬)が定義できず、**一萬と九萬を相互の次牌**とする(一萬→九萬、九萬→一萬)。
- これは標準関西サンマ慣行に基づく**確定仕様**であり、実装(#78 `src/domain/dora/indicator.ts`)と一致する。**異論があれば実装(#78)とともに見直す**余地を残すが、本 spec では本案を確定とする。

> 実ドラの赤フラグ(`isRed`)は牌集合の規約(5筒・5索は常に赤、1.2 / 4.4)に従って算出する。ドラの照合は牌種で行い、赤5そのものの1翻(上表)とは独立に加算される。実装は `src/domain/dora/indicator.ts`(`nextTile`)・`doraSet.ts`(`resolveDora`)。

**受け入れ基準**
- Given リーチ+表ドラ2枚設定+赤5を1枚+北2枚抜き / When 和了(裏ドラ2枚該当なし) / Then ドラ由来の翻が正しく合算される
- Given 表ドラ表示牌が九萬 / When 次牌写像 / Then 実ドラは一萬(本変種固有)
- Given 表ドラ表示牌が9筒 / When 次牌写像 / Then 実ドラは1筒(巡回)
- Given 表ドラ表示牌が北 / When 次牌写像 / Then 実ドラは東(風牌巡回)
- Given ドラ表示牌が西(実ドラ=北)+北をn枚抜き / When 和了 / Then ガリn翻+表ドラn翻(リーチ時は裏ドラn翻も)が二重計上される(Q16)
- Given ドラ表示牌が西以外(実ドラ≠北)+北を抜き / When 和了 / Then 抜き北はガリ翻のみで二重取りされない(Q16)
- 特性: オール赤5・ガリ・複数ドラめくりが重なり、満貫以上が頻発する

## 3.3 ソシー精算

**基本レート: 素点1点 = 1ソシー。**

精算 = ①素点(1点=1ソシー) + ②順位ウマ + ③祝儀 の合算。プレイヤーごとにソシーを累計する。

### ① 素点(オカ)
- 各プレイヤーの最終持ち点をそのままソシー換算(1点=1ソシー)。
- **オカ = 返し40,000 を基準**に配分。配給原点35,000×4人 − 返し40,000×4人 = **−20,000** を1位が受け取る(1位に +20,000 加点)。これによりウマ込みの精算総和はゼロになる。
- 集計対象は**4兄弟全員**(着席3人+抜け番1人)。持ち点は局をまたいで永続・抜け番中は不変(Q5・4.4)。

#### 精算入力の前提(#394)

①②の入力となる**最終持ち点は、合計が `配給原点 35,000 × 4 = 140,000` でなければならない**。素点は「持ち点 − 返し40,000」の総和なので、合計がずれるとその差がそのままソシー総和のずれになり、ウマ+オカ(総和ゼロ)では埋め合わされない。

- **供託リーチ棒**は場に残っている間この合計から抜けている。半荘終了時に残った供託は、精算前に最終持ち点へ畳み込む(帰属先は Q15/Q20 で確定 → 本ファイル 3.4「半荘終了時に場へ残る供託リーチ棒の帰属」)。
- **場に残る点棒はすべて**精算前に畳み込む必要がある。現状で残り得るのはリーチ棒だけだが、将来チョンボ罰符を供託方式で導入する場合(`質問リスト.md` Q29 未解決)も同じ扱いにしなければ合計が崩れる(→ #430)。
- 実装(`SoshiiLedger.applyRawScore` / `applyUma`)はこの合計を検証し、破れたら `RangeError` を投げる。破れても例外が出ないと「結果画面の精算表が合わない」形でしか現れず発見が遅れるため、被呼び出し側で防ぐ。

**受け入れ基準**
- Given 最終持ち点の合計が 140,000 でない / When 素点またはウマを適用 / Then `RangeError`(精算を進めない)
- Given 半荘終了時に供託が場に残っている / When 精算 / Then 残存供託を最終持ち点へ畳み込んでから適用する(合計 140,000 が回復する)

### ② 順位ウマ(千点単位)= 4人の最終順位に適用(Q13)

半荘終了時、**着席/抜け番を問わず4兄弟全員をその時点の持ち点で順位付け**し、4段ウマをそのまま割り当てる(3人に丸めない)。

| 順位 | ウマ |
|---|---|
| 1位 | **+10,000 ソシー**(表記「+10」) |
| 2位 | +5,000 ソシー(「+5」) |
| 3位 | -5,000 ソシー(「-5」) |
| 4位(最下位) | -10,000 ソシー(「-10」) |

- ウマ総和 = +10 +5 −5 −10 = **0**(千ソシー単位、総和ゼロ)。
- 千点=千ソシー(Q2)。同点順位の裁定は起家/席順の慣行に従う(実装で確定させてよい)。

### ③ 役満祝儀
- 役満和了時、**抜け番を含む和了者以外の3兄弟**が各**1,000ソシー**を和了者へ支払う(Q14 確定・ユーザー承認 2026-07-17 / #129)。祝儀移動 = 和了者 **+3,000** / 他3兄弟 各 **−1,000**。
- **先着1名のみ**(その半荘で最初の役満者)。
- **数え役満は対象外**。
- **パオ(責任払い)あり**: 大三元・大四喜・四槓子。パオ確定牌を打った者が責任払い。ただし**祝儀は別枠**で、パオでも支払者を責任者へ寄せず「抜け番含む他3兄弟から各1,000・先着1名」を維持する(3.1「本場・パオ・供託の点数移動と加算順序」・実装 `settlement.applyBonus` と一致)。

**受け入れ基準**
- Given 役満で和了 / When 祝儀確定 / Then 和了者 +3,000ソシー・**抜け番を含む他3兄弟が各 −1,000ソシー**(合計ゼロサム)
- Given 大三元をパオ確定打牌で確定 / When ロン和了 / Then 放銃者/パオ者が責任払い、祝儀は抜け番含む他3兄弟から各1,000ソシー(パオ別枠)
- Given 数え役満で13翻 / When 和了 / Then 点数は役満だが**祝儀は付かない**
- Given 支払者が「和了者以外の全兄弟がちょうど1回ずつ」でない(空・人数違い・重複・和了者自身を含む・未知のID) / When 祝儀を適用 / Then `RangeError`(残高も先着枠も書き換えない / #394)。祝儀が付かない呼び出し(先着済み・数え役満・非役満)でも同じく `RangeError`

> **支払者リストの前提(#394)**: 空リストは授受ゼロのまま**先着1名の枠だけを消費**し、以後その半荘で祝儀が一切付かなくなる。重複した支払者は和了者と支払者の相対スイングを 4,000 → 5,000 へ広げ、ウマの最小隣接差 5,000 とのマージン(通常 1,000)を食い潰して、**「ソシー累計順位(結果画面の順位)」と「持ち点順位(ウマ配分)」の一致**という不変条件を壊す。どちらも例外にならず精算結果だけが静かに壊れるため、`applyBonus` が加算前に検証する。

### 役満祝儀「全員から1,000」の支払者範囲 【判断ポイント / #89 論点② → 確定(ユーザー承認・抜け番含む他3兄弟)/ Q14 / #129】

> **確定(ユーザー承認 2026-07-17 / 採用 = (B) 抜け番を含む他3兄弟)。** 役満和了時の祝儀「全員から1,000」の「全員」= **抜け番を含む和了者以外の3兄弟**。同卓の敗者2人だけでなく、その半荘で抜け番だった兄弟も1,000ソシーを支払う。

SSOT(`docs/四兄弟麻雀ルール.md` §5「役満祝儀:全員から1000」)は、サンマで**抜け番(北家)が1人いる**本変種において「全員」がどこまでを指すかを明示していなかったため、ユーザー判断で以下の (B) に確定した:

| 解釈 | 支払者 | 祝儀移動(和了者 / 各支払者) |
|---|---|---|
| (A) 同卓の敗者2人のみ | 着席3人のうち和了者を除く2人(抜け番は対局外で不参加) | 和了者 +2,000 / 敗者2人 各 −1,000 |
| **(B) 抜け番を含む他3兄弟(確定)** | 4兄弟のうち和了者を除く3人(抜け番も支払う) | 和了者 **+3,000** / 他3人 各 **−1,000** |

- **実装挙動(確定)**: `src/domain/game/engine.ts` の `settleWin` が `state.order.filter((id) => id !== winnerId)`(= 抜け番を含む和了者以外の3兄弟)を `settlement.applyBonus` の `loserIds` に渡す(`applyBonus` 自体は支払者を呼び出し側指定にして中立化済み・#66/PR #88)。額・先着1名・数え役満対象外は Q2/Q8 で確定済みのため不変。祝儀のパオ別枠扱い(責任者へ寄せない)も本論点と独立に確定している。
- **選定理由**: SSOT の文言「全員」を4兄弟全体と読み、抜け番の点棒も局をまたいで永続(Q5)する四人回しの性質を重視して (B) を採る。祝儀は点棒(点数)ではなくソシーの直接授受であり、3.4 流局テンパイ料が「抜け番は点棒授受に含めない」とする点棒移動とは別枠のため、抜け番を含めることと矛盾しない。

### パオ(責任払い)の責任者判定と点棒移動 — 実対局結線の確定仕様 【判断ポイント / #99】

**対象役満**: 大三元・大四喜・四槓子(Q8・3.0 の「パオ対象」)。パオの**点棒移動**(責任者の負担額・折半・本場)は 3.1「本場・パオ・供託の点数移動と加算順序」を SSOT とし、実装 `src/domain/scoring/win-payment.ts`(`resolveWinPayment` の `paoResponsibleId`)と一致する。本節は**誰が責任者(`paoResponsibleId`)になるか**の判定を確定する。

**責任者(`paoResponsibleId`)の判定**

- 責任者 = **パオ確定牌を鳴かせた打牌者**。副露でパオ役満が「確定」に至った、その打牌を出した者を責任者とする。
  - **大三元**: 三元牌2種の刻子が既に副露で確定した状態で、**3種目の三元牌をポン/大明槓させた打牌者**。
  - **大四喜**: 風牌3種の刻子が確定した状態で、**4種目の風牌をポン/大明槓させた打牌者**。
  - **四槓子**: 3つ目までの槓が確定した状態で、**4つ目の大明槓を成立させた(槓材を打った)者**。
- **門前(暗刻・暗槓)や自摸・加槓のみで完成した役満にはパオが付かない**(責任者なし)。この場合 `paoResponsibleId` を渡さず、通常の点数移動(3.1)となる。

**点棒移動(3.1 と一致・`win-payment.ts` SSOT)**

| 和了種別 | 責任者と放銃者の関係 | 素点の負担 | 本場の負担 |
|---|---|---|---|
| ロン | 責任者 ≠ 放銃者 | 折半: 責任者 `ceil100(total/2)`、放銃者 `total − ceil100(total/2)` | 放銃者が `300×本場`(折半しない) |
| ロン | 責任者 = 放銃者 | その1人が全額 `total` | 放銃者(=責任者)が `300×本場` |
| ツモ | — | **責任者が全額** `tsumo.total`(他家は0) | 責任者が `300×本場`(簡略・3.1 参照) |

- **祝儀は別枠**(3.3③): パオでも役満祝儀は「**全員から1,000ソシー・先着1名**」を維持し、支払者を責任者へ寄せない(実装 `settlement.applyBonus` と一致)。

> **結線は別途(issue #99 残タスク)**: 上記の責任者**追跡ロジック(engine への結線)は本 spec では確定のみ**とし、実対局への組み込み(役満成立時に責任者を特定して `settleWin` から `paoResponsibleId` を渡す)は #97(鳴き/リーチ実装)マージ後の別ラウンドで行う。点棒移動そのものは `win-payment.ts` に実装済み。
> **確定の位置づけ**: 標準的なパオ(包)慣行に準拠。番組の一次情報に責任者判定の詳細は無いため、**標準慣行に基づく確定(見直し余地あり)**とする(#79/#83/#89 と同方針)。

## 3.4 供託・チョンボ

| 事象 | 処理 |
|---|---|
| リーチ棒 | 供託。和了者が回収(ダブロン相当は上家取り) |
| チョンボ | **満貫罰符相当を供託**扱い(暫定運用) |

上表は**局中**の供託処理(和了で回収・流局で場に持ち越し)を定める。**半荘終了時に場へ残る供託リーチ棒の帰属**は下記のとおり **1位取得**で確定(Q15)。同点最高で単独1位が存在しない場合は**席順上位が総取り**で確定(Q20)。

### 半荘終了時に場へ残る供託リーチ棒の帰属 【#106 → 確定(ユーザー承認・2026-07-17)/ Q15・Q20】

> **確定(ユーザー承認・2026-07-17 = 1位取得 / Q15・同点最高のうち席順上位が総取り / Q20)。** 半荘終了時に場へ残った供託リーチ棒(残存本数 × 1,000)は、**最終持ち点が最高**のプレイヤーの素点へ加算してから順位・精算を確定する。**同点最高で単独1位が存在しない場合は席順(起家に近い順)で最上位の1人が総取り**する。

SSOT(`docs/四兄弟麻雀ルール.md` §3「リーチ棒は供託扱い。ダブロン等が発生した場合は上家取り」)は**局中の回収規則**を定めるに過ぎず、**半荘終了時(南4流局・トビ等)に和了で回収されず場へ残った供託リーチ棒**の帰属は §3・§5 いずれにも記載がなかったため、ユーザー判断で以下を確定した(麻雀一般の「最終局トップ総取り」慣行に一致)。

**確定内容**:

- **1位取得**。半荘終了時点の最終持ち点が**単独最高**の者が、場に残る供託(残存本数 × 1,000)を**素点へ加算**して受け取る。これにより持ち点総和は `140,000` に復し、ソシー精算(素点+ウマ+オカ)は **zero-sum** を保つ。
- **最高点の裁定は Q19 に整合**。「最高点」は**抜け番を含む4兄弟全員**の最終持ち点に対する**厳密比較**で判定する(`endGame` の `residualRiichiRecipient` = `finishRound` の `dealerIsTop` と同じ比較基準)。
- **同点最高(単独1位なし)は席順上位が総取り(Q20 確定・ユーザー承認 2026-07-17 / issue #131)**。2人以上が最高点タイで終局した場合、残存供託は**同点最高者のうち席順で最上位(固定円環 `order` の先頭 = 起家に近い順 = 供託の上家取り慣行に準ずる)の1人が全取得**する。`order[0]` が起家(初局の親)で半荘を通じ不変のため、帰属先は端数なく一意に決まり、**この場合も zero-sum を保つ**。

**実装**: `src/domain/game/engine.ts` の `endGame` が精算(`applyUma`/`applyRawScore`)の**前段**で、残存供託(`state.riichiSticks × 1,000`)を `residualRiichiRecipient(state.order, points)` が返す帰属先(最高点=単独ならその1人、同点最高なら席順上位の1人)の `points` へ加算し `riichiSticks` を 0 にする。結線テストは `src/domain/game/engine.residual-riichi.test.ts`(残存供託ありで終局→単独1位が取得・zero-sum、同点最高2人/起家以外2人/3人/抜け番含む同点→席順上位が総取り・zero-sum)と `engine.melds-riichi.test.ts` で担保する。

**決着表示との整合(#282)**: `gameEnd` の決着表示(スペック6 6.3 / #277)は「局開始持ち点 + 表示デルタ = 表示持ち点」「供託カウント 0 との整合」を検算できる必要がある。このため `endGame` は残存供託の加算を最終局サマリ `lastRound.deltas[帰属先]` へも**畳み込み**(和了決着で複数局分の供託回収 `stickPayout` が和了者のデルタに含まれるのと同じ扱い)、帰属の内訳を `RoundSummary.residualSticks`(`recipientId` / `recipientName` / `sticks` / `points`)として記録する。UI(`GameBoard`)は `gameEnd` の hint・読み上げに「残存供託N本(N,000点)は◯◯が取得。」を併記し、帰属先が抜け番でも点差(`pointsDelta`)を表示する(`BenchArea`)。最終持ち点・順位・精算(`result`)自体は従来と不変(表示サマリのみの拡張)。回帰テストは `engine.residual-riichi.test.ts`(デルタ畳み込み・帰属記録・三者一貫)、`gameView.test.ts`(抜け番への点差写像)、`GameBoard.test.tsx`(hint 併記と表示整合)。

### 流局テンパイ料(荒牌平局)のサンマ配分 【判断ポイント / #99】

荒牌平局(山尽き=海底で誰も和了せず流局・2.1)時、**着席3人(東・南・西)**のテンパイ/ノーテンで点棒を授受する。**抜け番(北家)は対局外のため授受に含めない**(持ち点は局をまたいで不変=Q5・4.4)。実装 `src/domain/game/engine.ts`(`settleDraw` / #67, 定数 `NOTEN_POOL = 3000`)を SSOT とし、関西サンマ標準の**3,000点プール配分**を確定仕様とする。

- 総額 **3,000点** を、テンパイ者が均等に受け取り、ノーテン者が均等に支払う。
  - 各テンパイ者の受取 = `3000 / テンパイ人数 k`
  - 各ノーテン者の支払 = `3000 / ノーテン人数 (3 − k)`
- **全員テンパイ(k=3)/全員ノーテン(k=0)は授受なし**(点棒移動ゼロ)。

**確定配分表(着席3人・単位: 点):**

| テンパイ数 k | ノーテン数 | 各テンパイ受取 | 各ノーテン支払 | 授受総額 |
|---|---|---|---|---|
| 0 | 3 | — | 0(授受なし) | 0 |
| 1 | 2 | +3,000 | −1,500 | 3,000 |
| 2 | 1 | +1,500 | −3,000 | 3,000 |
| 3 | 0 | 0(授受なし) | — | 0 |

- 授受は総和ゼロ(k=1: 受 3,000 = 払 1,500×2 / k=2: 受 1,500×2 = 払 3,000)。
- **テンパイ連荘との整合(2.7 / Q6・rule §3)**: 親(東)がテンパイなら**連荘**(本場+1・席/抜け番/局番号すべて据え置き、2.5 の回転を行わない)、親ノーテンなら**親流れ**(2.5 の反時計回り1席回転・局番号+1)。**連荘/親流れは「親のテンパイ有無」のみで決まり**、テンパイ料の授受額(親が受け取る/支払う)とは独立に適用する。流局時は本場+1(2.7)。

> **確定の位置づけ**: 関西サンマ標準の「ノーテン罰符 計3,000点」を着席3人で均等割する運用。**4人打ちの1,000/1,500/3,000 系(場に4人)とは配分が異なり**、サンマ着席3人での均等割となる点に注意。番組の一次情報にテンパイ料の配分額は無いため、**標準慣行に基づく確定(見直し余地あり)**とし、実装(#67 `settleDraw`)と一致させる(#79/#83/#89 と同方針)。
